# Agentic Demo — Project Rules

## Best Practices
Read `.hermes/best-practices.md` before starting any task.
It contains project-wide rules, language-specific guidelines, and quality gates.

## Tech Stack
- **Language:** Python 3.11
- **Framework:** FastAPI 0.110+ (async)
- **Validation:** Pydantic v2
- **Server:** uvicorn
- **Testing:** pytest + pytest-asyncio + httpx
- **Linting:** ruff
- **Type checking:** mypy

## Build & Test Commands
- Install deps: `pip install -r requirements.txt`
- Run tests: `pytest tests/ -v`
- Run single test: `pytest tests/test_store.py::test_name -v`
- Lint: `ruff check src/ tests/`
- Auto-fix lint: `ruff check --fix src/ tests/`
- Type check: `mypy src/ --ignore-missing-imports`

## Auto-Validation Before Commit
Always run this pipeline before `git commit`:
1. `ruff check src/ tests/` — must pass
2. `mypy src/ --ignore-missing-imports` — must pass
3. `pytest tests/ -v` — must pass

If ALL pass → commit and continue
If ANY fail → stop and report to user

## Code Style
- Type hints on all public functions
- Pydantic models for all request/response
- No wildcard imports
- Use `from __future__ import annotations` for modern type syntax

## Git Workflow
- Branch naming: `feat/`, `fix/`, `refactor/`, `docs/`
- Commit format: Conventional Commits (`feat:`, `fix:`, `chore:`)
- Always run full validation pipeline before commit

## Architecture
- `src/models.py` — Pydantic request/response models
- `src/store.py` — in-memory URL store (core logic, no framework deps)
- `src/app.py` — FastAPI app (thin, delegates to store)
- `tests/` — mirrors src/ structure

## TDD Enforcement
- Write failing test FIRST (RED)
- Minimal implementation (GREEN)
- Clean up (REFACTOR)
- Every new function MUST have a test before implementation

## Auto-Update Documentation
After completing any task, agent MUST update relevant docs in `docs/`:
1. **API.md** — Add new API endpoints, models, store methods
2. **CHANGELOG.md** — Add new features under [Unreleased]
3. **HANDOFF.md** — Update current state, pending items, key files
4. **WORKFLOW.md** — Update if flow/branching changed
5. **INDEX.md** — Update flow diagrams if structure changed

Reference: docs/INDEX.md for which file to update when.

### Changelog Rules (STRICT)
- **Every feat: or fix: commit** MUST have a changelog entry
- Entry goes under `[Unreleased]` section in CHANGELOG.md
- Format: `- Description of change`
- Example: `- Add rate limiting to /shorten endpoint`
- The validation pipeline WILL FAIL if changelog is not updated
- Update BEFORE committing — not after
